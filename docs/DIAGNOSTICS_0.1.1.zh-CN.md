# v0.1.1：连接诊断使用说明

此版本针对 v0.1.0 的连接提示不明确问题，增加本地诊断。诊断信息有助于缩小排查范围，但不能自动确定具体网络故障根因。

## 更新与操作

1. 从本仓库构建并安装 `ros-tablet-viewer-0.1.1-debug.apk`。是否可覆盖安装取决于本地签名密钥是否一致；不同签名通常需要先卸载旧版，这会清除本地偏好。本仓库不提供旧版交付 APK。
2. 在“连接”窗口核对地址，例如 `ws://192.0.2.1:8765`（文档占位地址，请换成自己的机器人地址）。
3. 点击顶部“诊断”。查看 WebSocket、serverInfo、话题广播、订阅和数据接收的分层状态。
4. 点击“检测 TCP / Ping”。此检查由手机本地执行，目标是连接窗口当前填写的服务器，不是由远端云环境测试。
5. 点击“复制诊断”；如系统剪贴板不支持，可用“导出文本”后长按报告全选复制。分享报告前先检查并删除不想公开的地址和设备信息。

## 结果怎么理解

- DNS 失败：若填写的是域名，检查域名和手机 DNS。数字 IP 不需要依靠域名解析服务。
- TCP 连接成功：该地址和端口可建立 TCP 连接，不证明服务一定是 Foxglove，也不证明 TLS 或 WebSocket 握手成功。
- TCP 拒绝：可能端口未监听或网络设备明确拒绝。检查车端监听和防火墙日志，不能仅凭此结果认定具体原因。
- TCP 超时：可能路由、VPN、防火墙、丢包或服务无响应；报告不会擅自归因。
- Ping 成功：目标回应 ICMP；不证明 8765 端口可用。
- Ping 未回应或不可用：可能系统不提供工具或禁止 ICMP，不能因此断定 bridge 不可达。
- WebSocket 已打开但无 serverInfo：传输已建立，但尚未确认 Foxglove 服务信息；不能显示为“所有功能正常”。
- 收到 serverInfo 但未广播话题：检查 bridge 是否连接到正确 ROS Master、是否已有发布者，以及话题白名单。
- 已广播零话题：网络连接与零话题是不同问题，不能把它当作 TCP 连接失败。
- 已有话题但不兼容：检查消息 encoding/schema，当前应用仅支持 ROS1 二进制消息。
- 已订阅但暂未收到数据：检查发布频率、发布者和桥接日志；静态或低频话题长时间不更新可能正常。
- 关闭码 1006：通常表示异常关闭且浏览器没有收到有效关闭帧，本身不是某一种网络故障的确定证据。

## 本地信息与隐私

诊断时间线有长度上限，记录连接事件，不导出点云或图像原始数据。常见 URL 凭据、查询参数值和令牌会做隐藏处理，但无法保证任意第三方自定义错误文本都不含敏感信息，分享前仍需检查。报告可能包含服务器地址、名称、Android/WebView 版本和设备型号。

检测只在点击按钮后运行，包含超时和取消机制。不会扫描其他端口，不修改网络、防火墙或 VPN，不忽略 TLS 证书错误，也不向 ROS 发布话题或调用控制服务。

## 验证边界

本地原生诊断代码、输入边界、授权通道与故障状态由自动测试和源码检查验证。开发环境没有物理 Android 手机，实际系统的 ICMP 工具、VPN 路由及 WebView 网络行为仍以手机运行结果为准。
